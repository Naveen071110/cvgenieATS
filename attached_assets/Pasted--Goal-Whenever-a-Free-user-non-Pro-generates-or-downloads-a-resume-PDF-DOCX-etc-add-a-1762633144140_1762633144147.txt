**Goal:**  
Whenever a Free user (non-Pro) generates or downloads a resume (PDF, DOCX, etc.), add a visible watermark such as "Generated with CVGenie – Upgrade for no watermark". Pro users receive watermark-free documents. Do this without breaking existing generation logic.

**Instructions:**

1. **Locate Subscription/Tier Check Logic:**
   - Use the provided subscription helpers (from `subscriptionQueries.ts`, `subscriptionUtils.ts`, or the session) to get the user’s current status (`isPro`, `subscriptionStatus`).

2. **Find Resume Generation Handler:**
   - In `routes.ts` or wherever the main resume generation API/endpoint exists, identify the code branch that handles file creation for generation and download.

3. **Implement Watermark Logic:**
   - After confirming the user’s status, add logic:
     - If Pro (usually `isPro = true` or `subscriptionStatus === 'active'`), generate resume/download as usual—**do not** add watermark.
     - If Free, apply a visible watermark to the generated document before sending it for download or display. The watermark should say:  
       “Generated by CVGenie – Upgrade to Pro to remove watermark”  
     - For PDF/Docx: You can place this diagonally across each page, or in the header/footer.
     - For HTML/preview: Overlay a semi-transparent div or small fixed element.

     Example in pseudocode:
     ```js
     if (user.isPro) {
         generateResumeWithoutWatermark(...);
     } else {
         generateResumeWithWatermark(..., "Generated by CVGenie – Upgrade for no watermark");
     }
     ```
   - If using a document generation library (like pdf-lib, jsPDF, or docx), use their API to overlay/add the watermark string.

4. **Frontend Preview:**
   - If resumé previews in the browser are rendered for Free users, ensure the watermark appears visually in the preview as well.

5. **Testing:**
   - Confirm Free users always get a watermarked file BOTH in the preview and on download.
   - Confirm Pro users never receive a file with any watermark.
   - Test with multiple users (Free and Pro) to verify.

6. **Non-Disruptive Change:**  
   - Do NOT change any logic for users already assigned as Pro or resume generation for active subscriptions.
   - Isolate changes to just the watermark-adding branch for Free users.

7. **(Optional, for future clarity):**
   - Consider adding a config or constant for the watermark message and style (for easy updates later).

***

**Deliverables:**  
- Resume generation logic forks on user tier and applies watermark only for Free users.
- Watermarks are clearly visible in output and browser preview for Free users, not present for Pro.
- No impact to other existing code or logic.
