Context
The blog-search.tsx component calls onFilteredPosts(filteredPosts) inside a useMemo, but onFilteredPosts is sometimes undefined or not a function. Also, invoking callbacks is a side effect and should be done in useEffect, not useMemo. Please implement the following fixes.

Tasks

Add a defensive no-op default and proper typing

In client/src/components/blog-search.tsx, update the props typing so onFilteredPosts is optional and typed as a function:
type BlogSearchProps = {
posts: PostMeta[];
onFilteredPosts?: (posts: PostMeta[]) => void;
};

Add a local safe callback with a default no-op:
const handleFiltered = typeof onFilteredPosts === 'function'
? onFilteredPosts
: () => {};
This ensures calling it won’t throw even if the parent didn’t pass the prop. Passing functions via props should either be guaranteed by typing or guarded by typeof checks.

Move the side effect to useEffect

Replace the useMemo that calls onFilteredPosts with useEffect:
useEffect(() => {
handleFiltered(filteredPosts);
}, [filteredPosts, handleFiltered]);
Side effects belong in useEffect, not useMemo; useMemo is only for memoizing computed values, not for invoking callbacks.

Stabilize the callback reference (optional enhancement)

If the linter warns about handleFiltered changing identity, wrap a memoized proxy with useCallback to avoid unnecessary effects:
const emitFiltered = useCallback((p: PostMeta[]) => handleFiltered(p), [handleFiltered]);
useEffect(() => { emitFiltered(filteredPosts); }, [filteredPosts, emitFiltered]);
This reduces re-renders and effect triggers when parents pass unstable function identities.

Update all call sites

Find where <BlogSearch ... /> is used (likely in blog index page) and either:

Pass a real handler: onFilteredPosts={(list) => setVisiblePosts(list)}

Or omit the prop if not needed; the component will now no-op safely.
Common “is not a function” happens when a prop expected to be a function is missing or a different type; ensure all uses pass a function or leave it undefined.

Add prop validation or TS checks

If using PropTypes, add:
BlogSearch.propTypes = { onFilteredPosts: PropTypes.func };

If using TypeScript only, keep the optional function type as in step 1; this prevents accidental non-function values.

Test

Run the app and visit the blog page.

Verify filtering works and no runtime error appears when onFilteredPosts is omitted.

Confirm no side-effect happens multiple times unexpectedly; the effect should only run when filteredPosts changes.

Reference rationale

Use useEffect for side effects; useMemo is for memoizing values only. Invoking callbacks in useMemo is an anti-pattern and can be unreliable.

Guard optional function props and prefer a no-op default or typeof check before invoking.

Stabilize callbacks with useCallback to avoid excessive effect triggers.

If any other components call non-existent callbacks similarly, please apply the same pattern (optional function typing, default no-op, useEffect for side effects).
