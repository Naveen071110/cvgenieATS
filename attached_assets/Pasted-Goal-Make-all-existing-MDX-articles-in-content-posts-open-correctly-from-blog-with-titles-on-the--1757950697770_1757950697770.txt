Goal
Make all existing MDX articles in content/posts open correctly from /blog, with titles on the blog index matching each post’s frontmatter.title. Ensure the routing is robust for future posts without more code changes.

Tasks

Detect router and MDX config

Identify if the app uses the Pages Router or the App Router.

Confirm MDX support is configured and pageExtensions include md/mdx (or MDX plugin is enabled). If missing, add it.

Verify the blog index route (/blog) exists and there is a dynamic post route at either:

Pages Router: pages/blog/[slug].tsx

App Router: app/blog/[slug]/page.tsx

Normalize data layer

Create or fix a posts utility (e.g., lib/posts.(ts|js)) that:

Reads all files at content/posts/*.mdx.

Extracts frontmatter: title, slug, description, date, updated, tags, ogImage.

If slug is missing, derive it from the filename (kebab-case).

Returns an array of PostMeta objects sorted by date (desc).

Exposes getAllPosts(), getAllSlugs(), getPostBySlug(slug).

Guarantee that getAllSlugs() returns a string[] and getAllPosts() contains valid title and slug for every post.

Blog index (/blog)

Render the list using frontmatter.title (not filename).

Build links using <Link href={/blog/${post.slug}}>.

Remove any duplicate path fragments like /blog/blog/ or missing /blog prefix.

If there’s search/tags, keep them working; do not change URL structure beyond fixing hrefs.

Dynamic post page (/blog/[slug])

Pages Router:

Implement getStaticPaths() to return paths for all slugs and fallback: false (or blocking).

Implement getStaticProps({ params }) to load and serialize MDX content by slug.

App Router:

Implement export async function generateStaticParams() { return getAllSlugs().map(slug => ({ slug })); }

Load and render the MDX by slug in the page component.

Optionally add export const revalidate = 3600 for ISR so new posts appear without a full rebuild.

Ensure the post page <h1> uses frontmatter.title.

Title consistency

On the blog index, show post.title from frontmatter.

On each post page (/blog/[slug]), show the same frontmatter.title in the H1 and in metadata.

If any post lacks title in frontmatter, log a warning and fall back to a prettified filename, but prefer adding a proper title to frontmatter.

Hardening and guards

Add a small “content:check” script to validate that each MDX file has a unique slug, title, and date, and log warnings otherwise.

Ensure the blog index doesn’t break if there are zero posts.

Make the tag filter and search components tolerant of missing/undefined props (default to empty arrays and no-op callbacks).

Test

Rebuild and open /blog.

Click each of the 4 existing articles; they must open at /blog/{slug}.

Verify the titles on index and detail pages match the frontmatter titles.

Deliverables

List of files created/modified (data layer, index page, dynamic page, MDX config).

A brief note of any frontmatter the agent had to update (e.g., adding slug/title).

Confirmation that adding a new file at content/posts/new-article.mdx automatically shows in /blog and opens at /blog/new-article.

Notes

Do not change any API or generator functionality—only fix the blog routing and metadata usage.

Keep URLs lowercase and slug-based. Avoid adding “/blog/blog/” in any href.

Preserve existing styling and theme.
